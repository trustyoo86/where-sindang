# place-search-verify — 검증 매뉴얼

## 트리거
검색 로직/UI 산출물이 나온 직후. 전부 끝나고 한 번이 아니라 **산출물별 점진 검증**.

## 작업 절차
1. search-engineer 산출 직후: `search.test.ts` 케이스와 시그니처를 검증.
2. search-ui 산출 직후: 통합 동작 + 디자인을 검증.
3. 명령 실행: `yarn lint`, `yarn test`, `yarn build`(출력을 근거로 보관).
4. `artifacts/04-verification.md`에 판정과 근거를 기록.

## 검증 케이스 (최소)
| 유형 | 입력 | 기대 |
| --- | --- | --- |
| 정상 | "로스터리" | "신당 로스터리"만 남음 |
| 애매 | "  로스터리  " / 대소문자 | 정규화되어 매칭 |
| 실패하기 쉬움 | "" (빈 검색어) | 전체 표시 |
| 실패하기 쉬움 | "없는가게" | 0건 안내 문구 |

## 디자인 검증 (DESIGN.md)
- [ ] #ff385c가 검색 버튼/활성 상태에만 쓰였는가
- [ ] border-radius가 허용값(4/8/14/20/32/50%)인가
- [ ] 검색 pill에만 그림자, 카드엔 없음

## 출력 형식 (`artifacts/04-verification.md`)
- 케이스별 PASS/FAIL
- 실행한 명령과 결과 요약(근거)
- 디자인 위반 항목
- FAIL이면: **어느 agent가 무엇을 고쳐야 하는지**

## 품질 체크
- [ ] 근거(명령 출력/코드 인용) 없이 PASS 적지 않음
- [ ] 기능 코드 직접 수정하지 않음(반려만)
- [ ] 통과 시 사람 승인 게이트로 넘기라고 알림

## 예외 상황
- 빌드/테스트가 환경 문제로 실패하면, 기능 결함과 구분해 기록한다.
